# Building Map Plugin

## Requirements

- git
- Node.js 22+ (see `.nvmrc`) and npm
- Docker, for running a local Grafana

## Install process

- Clone this repository.

- Install plugin package dependencies

```sh
npm ci
```

If you are using Docker, the two steps above can be done as follows:

```sh
# First cd into this plugin's folder.
docker run -it --rm -v "$PWD":/usr/src/app -w /usr/src/app node:22 npm ci
```

## Build process

1. Build the plugin in development mode and rebuild on change

   ```bash
   npm run dev
   ```

2. Build the plugin in production mode

   ```bash
   npm run build
   ```

The build output lands in `dist/`, which is what the Grafana container mounts
as the plugin directory.

## Checks

```bash
npm run typecheck   # tsc --noEmit
npm run lint        # eslint (use `npm run lint:fix` to autofix)
npm run test:ci     # jest, single run
```

## Test / Run

1. Build the plugin at least once so `dist/` exists

    ```bash
    npm run build
    ```

2. Launch services (Grafana, CrateDB and TimescaleDB)

    ```bash
    docker compose -p map-panel up -d
    ```

    The Grafana version can be overridden, e.g.
    `GRAFANA_VERSION=12.3.0 docker compose -p map-panel up -d`.

3. Import database

    ```bash
    sh populate_db.sh
    ```

   Data sources and the example dashboards are provisioned automatically from
   `provisioning/` and `dashboards/`, so there is no manual set-up step.

   To add data sources of your own, such as ones with real credentials, put
   them in a file ending in `.local.yaml` under `provisioning/datasources/`.
   Grafana loads it with the others, and git ignores it, so it is never
   committed. It needs the usual `apiVersion: 1` and `datasources:` header.

4. After changing code, rebuild and restart Grafana

    ```bash
    npm run build && docker compose -p map-panel restart grafana
    ```

**NOTE:** Unless you remove the docker volumes, you only need to import the
database the first time.

At this point log in to Grafana using admin/admin and you should be able to see
a dashboard called `Dashboard Map` in the `Examples` folder.

## Updating the scaffolding

The build configuration under `.config/` is generated by
[`@grafana/create-plugin`](https://grafana.com/developers/plugin-tools) and
should not be edited directly. To pull in a newer version of it:

```sh
npx @grafana/create-plugin@latest update
```

See [extend configurations](https://grafana.com/developers/plugin-tools/how-to-guides/extend-configurations)
for the supported ways to customise it.

## Releasing a new version

1. Update the CHANGELOG.md document to include changes of the new release
1. Bump `version` in `package.json` to match
1. Tag the master with the new version:
    ```sh
    git tag v2.0.0
    git push origin v2.0.0
    ```
1. Complete the release information in github.

## Notes

Default start page url: http://localhost:3000
Default user/pass is admin/admin.
